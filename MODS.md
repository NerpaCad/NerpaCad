# Моды NerpaCad

Мод добавляет в NerpaCad своё:
- **роботов** — вид, размеры, колёса, скорость, площадки под датчики и, если хочется, свои модели модулей датчиков;
- **героев** — свою модель, которая ходит как один из встроенных героев (Нерпа, Читик или Геннадий);
- **детали поля** — рельеф (встаёт по клеткам поля) и декор: статичные, по которым ходят и ездят, или такие, которые можно толкать.

Мод — это **только данные**: файл `mod.json` и 3D-модели. Программного кода в моде нет, и программа его не выполняет, поэтому мод безопасно ставить на любой компьютер, в том числе школьный.

Формат открытый: делайте моды для своих роботов и делитесь ими.

## Где лежат моды

| Где | Путь |
|---|---|
| Windows | `%APPDATA%\NerpaCad\mods\` |
| Linux | `~/.config/NerpaCad/mods/` |
| При разработке (`npm run dev`) | ещё `mods/` в корне проекта (не попадает в git) |

Проще всего найти папку так: «О программе» → «Открыть папку модов». Каждый мод — отдельная папка внутри неё. Положите папку и перезапустите программу. В «О программе» видно, какие моды подключены, а у неподключившегося — что с ним не так.

## Пример

```
mods/
  mybot/
    mod.json
    mybot.glb
    sonar.glb
```

## mod.json

| Поле | Что это |
|---|---|
| `format` | всегда `"nerpacad-mod"` |
| `formatVersion` | версия формата, сейчас `1`. Мод более новой версии программа не подключит и скажет об этом |
| `id` | id мода: латинские буквы, цифры, `.`, `_`, `-` (до 64 знаков) |
| `name` | название: строка или `{ "ru": …, "en": …, "zh": … }` |
| `version`, `author`, `license`, `description`, `homepage` | для списка модов в «О программе» (необязательные) |
| `robots` | роботы мода (до 16) |
| `heroes` | герои мода (до 64, необязательное) |
| `props` | детали поля (до 64, необязательное) |

В моде должно быть хоть что-то одно: роботы, герои или детали. Id роботов, героев и деталей уникальны среди всех модов; `seal`, `cheetah` и `pigeon` заняты встроенными героями.

Текст бывает строкой или объектом по языкам; если нужного языка нет, берётся английский, затем русский.

## Робот

Все размеры — в миллиметрах. Система координат робота: начало на полу между ведущими колёсами, **X — вперёд, Y — влево, Z — вверх**.

| Поле | Что это | Пределы |
|---|---|---|
| `id` | id модели робота; он записывается в проекты. Уникален среди всех модов, `nerpabot` занят | |
| `name` | название в панели и в свойствах | |
| `wheelRadius` | радиус ведущих колёс | 5…150 |
| `track` | колея: расстояние между центрами колёс | 20…600 |
| `maxSpeed` | скорость при мощности моторов 100 %, мм/с | 10…2000 |
| `radius`, `height` | цилиндр, которым робот сталкивается и выбирается мышью | 20…300, 10…500 |
| `centerX` | центр этого цилиндра впереди начала координат (необязательное, 0) | −200…200 |
| `sensorSpot` | радиус пятна пола, которое видит датчик линии (необязательное, 4) | 1…30 |
| `sensorReach` | как далеко от центра площадки датчик линии смотрит в пол (необязательное, 50) | 0…200 |
| `pads` | площадки под датчики (до 16) | |
| `model` | 3D-модель робота | |
| `modules` | свои модели модулей датчиков (необязательное) | |

Если число вне пределов, оно подтягивается к ближайшему краю, а в «О программе» появляется замечание. Без обязательного числа робот не подключается.

**Площадка:** `port` — номер порта в блоках (целое 1…32, у каждой свой), `x`, `y` — центр, `z` — высота поверхности площадки над полом, `facing` — куда смотрит модуль на ней, в градусах (0 — вперёд, 90 — влево, 180 — назад).

## Модель

| Поле | Что это |
|---|---|
| `file` | файл `.glb`, `.gltf` или `.fbx` **внутри папки мода** (можно в подпапке: `models/bot.glb`). Пути с `..`, абсолютные пути и ссылки не принимаются |
| `scale` | сколько миллиметров в единице модели: метры — 1000, сантиметры — 10, миллиметры — 1 (по умолчанию 1) |
| `forward`, `left`, `up` | какая ось модели смотрит вперёд, влево и вверх: `+x` `-x` `+y` `-y` `+z` `-z`. По умолчанию `+x`, `+y`, `+z`. Оси должны быть разными и не зеркалить модель |
| `offset` | сдвиг после поворота и масштаба, `[x, y, z]` мм |
| `colors` | раскраска деталей по имени: `{ "match": регулярное выражение, "color": "#rrggbb", "roughness", "metalness", "opacity" (0…1), "emissive": "#rrggbb" }`. Срабатывает первое подходящее правило (без учёта регистра) |
| `defaultColor` | цвет деталей, которым не подошло ни одно правило. Без него они остаются со своими материалами из файла. Если задан, картинки (текстуры) модели не загружаются — удобно для FBX, у которых текстуры потерялись |
| `board` | (модули) регулярное выражение для детали-платы: она красится в цвет вида датчика (линия — зелёный, дальномер — синий, касание — красный, свет — жёлтый, фонарик — оранжевый) |
| `led` | (фонарик) деталь-светодиод, которая загорается, когда фонарик включён (по умолчанию `^diode$`) |

У модели робота начало координат — пол между ведущими колёсами. Модели glTF (GLB) обычно в метрах и с осью Y вверх: `"scale": 1000, "up": "+y"`; куда смотрит перед, видно в редакторе, где модель делалась.

## Модули датчиков

`modules` — свои модели для `line`, `ultrasonic`, `touch`, `light`, `flashlight`. Для видов, которых нет, берутся встроенные модули NerpaCad.

Модуль ставится в систему координат площадки: **X — наружу, по направлению `facing`; Z — вверх от поверхности площадки**; начало — центр площадки. Чтобы показания совпадали с моделью, держите размеры встроенного модуля:
- плата 70 × 31 мм, от 11 мм позади центра площадки до 59 мм наружу;
- излучатели дальномера — на 59 мм наружу, на высоте 13 мм;
- кнопка касания — на 66 мм, на высоте 12 мм;
- глазок датчика света и светодиод фонарика — на 52 мм, на высоте 15 мм.

## Герой

```json
"heroes": [
  {
    "id": "fox",
    "name": { "ru": "Лиса", "en": "Fox" },
    "like": "cheetah",
    "model": { "file": "fox.glb", "scale": 1000, "forward": "+z", "left": "+x", "up": "+y" },
    "clips": { "idle": "^idle$", "walk": "walk", "run": "gallop" },
    "tint": "^body",
    "color": "#e07a2e"
  }
]
```

| Поле | Что это |
|---|---|
| `id`, `name` | как у робота |
| `like` | как герой двигается и что умеет: `seal` (ползает, плавает), `cheetah` (ходит, бегает, прыгает на уступы, ползёт), `pigeon` (летает, ходит) |
| `model` | модель, как у робота (`file`, `scale`, оси, `colors`, `defaultColor`). Программа сама подгоняет её под длину героя, на которого он похож (Нерпа — 25 см, Читик — 34 см, Геннадий — 16 см), и ставит на пол |
| `clips` | какие анимации модели играть: `idle`, `walk`, `run`, `swim`, `fly`, `leap`, `takeoff`, `land`, `touchdown`, `fall`, `crouch`, `crawl` — регулярные выражения по именам анимаций. Если не указано, ищутся анимации с обычными именами (idle, walk, run, swim, fly, jump). Без подходящей анимации герой просто стоит в своей позе |
| `tint` | (необязательное) регулярное выражение: какие детали модели красить цветом героя из палитры. Без него модель остаётся в своих цветах |
| `color` | (необязательное) цвет нового героя |

Блоки, звуки и всё поведение — от героя из `like`.

## Детали поля

```json
"props": [
  {
    "id": "bridge-stone",
    "name": { "ru": "Каменный мост", "en": "Stone bridge" },
    "section": "relief",
    "model": { "file": "bridge.glb", "scale": 1000, "up": "+y", "forward": "+z", "left": "+x" }
  },
  {
    "id": "barrel",
    "name": { "ru": "Бочка", "en": "Barrel" },
    "section": "decor",
    "static": false,
    "mass": 120,
    "model": { "file": "barrel.glb", "scale": 10 }
  }
]
```

| Поле | Что это |
|---|---|
| `id`, `name` | как у робота |
| `section` | где деталь в панели: `relief` — во вкладке «Рельеф» (ставится на середину клетки поля), `decor` — во вкладке «Декор» (по умолчанию) |
| `model` | модель, как у робота. Деталь ставится на пол, по центру своего следа |
| `static` | `true` (по умолчанию) — деталь не двигается, роботы и герои заезжают и заходят на неё, упираются в стенки, проезжают под аркой; `false` — её можно толкать |
| `mass` | (для `"static": false`) вес в граммах; без него — по объёму, как у пластика |

Треугольники детали записываются в проект, поэтому проект откроется и без мода: деталь будет простой серой фигурой той же формы и будет так же мешать проезду. Для правил хождения берутся все треугольники модели (до 200 000), для толкания — её выпуклая оболочка.

## Проекты и моды

- Робот хранит в проекте `id` своей модели.
- Если мода на компьютере нет, проект всё равно открывается, а программа предупреждает: робот показан и ездит как NerpaBot, герой выглядит как тот, на кого похож (`like`), деталь — простая фигура той же формы. Всё остаётся в файле, и с модом станет прежним.
- Сменить модель робота можно в его свойствах. Датчики на площадках, которых у новой модели нет, снимаются.

## Проверка мода

Откройте «О программе». Подключённый мод показан со своими роботами, героями и деталями. Если мод не подключился, рядом написано почему (например, `robots[0].model.file: a .glb, .gltf or .fbx file in the mod's folder is needed`). Подробности есть и в консоли разработчика (Ctrl+Shift+I).
